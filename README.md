# University Portal MCP

Локальный stdio MCP для двух учебных систем: Moodle **eng.sbcde.by** и **it-sb.by**. Он даёт агенту структурированный доступ к своим курсам, материалам, заданиям, срокам, оценкам и посещаемости. Есть отдельные инструменты для сохранения и сдачи собственных работ и тестов.

Microsoft MarkItDown читает PDF, DOCX, PPTX, XLSX, HTML и текст локально, без LLM и облачного OCR. Оригинал и Markdown сохраняются в кэше; длинные материалы читаются частями.

## Установка по ссылке

Передай другу ссылку на этот репозиторий. В Codex с доступом к локальному компьютеру можно написать:

> Установи мне MCP из https://github.com/Flimu1/university-portal-mcp. Прочитай README и AGENTS.md, выполни автоматическую настройку и открой страницу входа. Пароль я введу сам.

Агент скачает проект, создаст отдельное окружение Python и подключение Codex. В браузере откроется мастер: войди в свой аккаунт **eng.sbcde.by**, при желании отдельно подключи **it-sb.by**, нажми «Завершить настройку». Затем перезапусти подключение MCP или открой новый чат и попроси показать свои курсы.

GitHub-ссылка сама по себе не является адресом MCP-сервера: агент использует её для локальной установки. Чужой аккаунт, файлы и расписание проверок не переносятся.

### Одна команда после скачивания

Нужен Python **3.11+**. На macOS/Linux:

```sh
python3 install.py
```

На Windows:

```powershell
py -3 install.py
```

Если доступен `uv`, он может подготовить нужную версию Python:

```sh
uv run --python 3.13 --no-project install.py
```

Установщик ставит зависимости в `.venv`, сохраняет остальные настройки Codex и открывает локальную страницу входа. Пароль вводится человеком в этой странице, передаётся для входа только соответствующему порталу и не записывается на диск. На компьютере сохраняется проверенный Moodle API-токен; для IT — отдельная сессия. Отправлять пароль агенту или вручную редактировать конфиг не нужно.

Данные находятся в папке пользователя: macOS — `~/Library/Application Support/UniversityPortalMCP`, Linux — `$XDG_DATA_HOME/university-portal-mcp` или `~/.local/share/university-portal-mcp`, Windows — `%LOCALAPPDATA%/UniversityPortalMCP`. Они не входят в Git. Кэш Moodle разделён по аккаунтам; существующие подключения по старому формату остаются совместимыми. На Unix файлы авторизации имеют права `0600`; на Windows используются права каталога пользователя.

### Проверка и повторный вход

Запусти через Python из установленной `.venv` (на Windows это `.venv/Scripts/python.exe`):

```sh
.venv/bin/python -m university_mcp.onboarding --doctor --live
.venv/bin/python -m university_mcp.onboarding
```

Первая команда проверяет настоящий доступ без сдачи работ. Вторая снова открывает мастер; действующий Moodle-токен проверяется и сохраняется, поэтому можно обновить только IT. Срок доступа определяет университет. Вход через SSO, MFA или изменившуюся форму может потребовать обычного браузерного входа; для Moodle остаётся помощник `python -m university_mcp.auth --auth-file <путь к auth.json>`. Не вставляй cookies в чат.

Для агента или тестовой установки доступны `--no-browser`, `--configure-only`, `--data-dir`, `--codex-home`. `--configure-only` настраивает MCP, но не означает успешный вход. `CODEX_HOME` учитывается. Если имя `university_portal` занято другой установкой, настройка остановится; `--replace` применяй только при намеренной замене. Конфиг сохраняется атомарно, первоначальная копия — рядом как `config.toml.university-backup`.

Сам MCP не включает периодические проверки и не начинает сдавать работы при установке. Это отдельные действия по просьбе владельца аккаунта. Удаление репозитория или `.venv` остановит установленное подключение: держи проект в постоянной папке.

[Официальная инструкция Codex](https://learn.chatgpt.com/docs/extend/mcp) описывает локальные MCP и перезапуск подключения.

## 26 инструментов

| Инструменты | Что делают |
|---|---|
| `portal_status`, `list_courses`, `get_course` | Авторизация, свои курсы, разделы и доступные элементы |
| `list_assignments`, `get_activity` | Условия, сроки, ограничения и вложения |
| `list_materials`, `download_material`, `read_material` | Поиск файлов, оригиналы, извлечённый текст |
| `search_materials` | Поиск по названиям, тексту элементов и именам файлов; не по телам непрочитанных документов |
| `list_deadlines`, `get_submission_status` | Ближайшие сроки и фактическое состояние сдачи |
| `save_assignment_submission`, `submit_assignment` | Сохранить собственную работу и сдать её с проверкой результата |
| `get_quiz_status`, `start_quiz_attempt`, `get_quiz_attempt`, `save_quiz_answers`, `finish_quiz_attempt` | Правила теста, свои попытки, ответы и проверенное завершение |
| `list_grades`, `get_course_grades` | Опубликованные оценки Moodle и отзывы по элементам |
| `get_course_progress` | Прогресс по отслеживаемым элементам, включая завершённые с неудачей |
| `list_calendar_events`, `list_announcements` | Доступные события и новости учебных курсов |
| `get_study_overview` | Сводка Moodle и изменения относительно локального снимка |
| `get_it_grades`, `get_it_attendance` | Официальные оценки и посещаемость из отдельной IT-системы |

Обычная цепочка чтения: `list_courses` → `get_course` → `get_activity` → `read_material`. `module_id` берётся из структуры курса, `material_id` — из списка материалов. Произвольные URL и функции API не принимаются. Если есть `next_offset`, дочитай результат следующей страницей.

Сводка различает **сдано**, **ожидает оценки** и **оценено**. Неизвестная или скрытая оценка остаётся `null`; ноль сохраняется как оценка. Для каждого диапазона `days` ведётся отдельный снимок; первый снимок не создаёт исторических уведомлений. Новые записи обозначают впервые обнаруженные в этом диапазоне элементы, а не обязательно недавно созданные. `update_baseline=false` показывает изменения, `true` подтверждает их локально. Частичные ошибки возвращаются в `warnings`; ошибка авторизации не обновляет снимок. Новости и календарь в сводке имеют ограниченный предпросмотр — отдельные инструменты позволяют дочитать их полностью.

Примеры запросов: «Покажи ближайшие дедлайны», «Прочитай лекцию по балансу», «Какие работы уже сданы, но ещё не оценены?», «Покажи мои оценки и посещаемость в IT за выбранный семестр».

## Оценки и посещаемость IT

Подключаются через необязательный второй шаг мастера с собственным логином IT-системы. Он использует обычную форму входа, официальный переход `SessionTransfer.aspx` и проверяет отчёт перед сохранением сессии. Пароль не хранится. При изменении формы, MFA или истечении сессии возвращается ошибка с просьбой войти снова; успешный вход не обещается без проверки отчёта. Новый вход этим способом покрыт синтетическими HTTP-тестами; чтение самих IT-отчётов проверено на действующей сессии. Для аккаунтов с другим способом входа может понадобиться адаптация.

Первый вызов `get_it_grades` возвращает текущий выбор и допустимые `options`. Передай их ID в `program`, `term`, `course`, `section`. Фильтры зависимы и применяются в этом порядке. Один отчёт охватывает **один предмет, семестр и подгруппу**. Пропущенные фильтры сохраняют выбор сервера — это не обязательно последний семестр и не все курсы. Для нескольких предметов запроси их последовательно. Фильтрация использует POST, но не меняет оценки или посещаемость.

Оценки IT и Moodle возвращаются отдельно: общего подтверждённого соответствия ID курсов нет. IT сохраняет обозначения оценок и посещаемости как в источнике. Отсутствие дат занятий означает `available=false`, а не полную посещаемость. Разбор проверен для наблюдаемой русской разметки; изменение языка или структуры отчёта приведёт к явной ошибке.

## Сдача и качество документов

Инструменты записи меняют настоящий портал. Подготовленные файлы должны находиться внутри разрешённой папки сдачи. Существующие вложения черновика сохраняются; сданные или заблокированные работы не перезаписываются. Некоторые задания сдаются сразу при сохранении — смотри фактический статус. Успешная загрузка сама по себе не подтверждает сдачу.

Запуск теста может потратить попытку и включить таймер. Сначала прочитай правила; затем сохраняй ответы по страницам и проверяй `finished`. Скрытые материалы и действия преподавателя не предоставляются.

В MCP-инструкциях закреплены короткие тексты простым языком, HumanWriting при его наличии, отсутствие лишних вступлений и шаблонных оборотов. Для презентаций заданы ясная последовательность, короткий текст, читаемая типографика, содержательные схемы, редактируемые таблицы и графики, проверка каждого слайда. Условия преподавателя, число слайдов и предоставленные визуальные образцы имеют приоритет. Навыки используются агентом в клиенте; MCP сам не генерирует документы и не устанавливает навыки.

## Ограничения и приватность

- Только собственный доступ. Нет сообщений, выставления оценок, произвольных API-вызовов или серверного администрирования.
- Структура Moodle кэшируется до 300 секунд; для обновления есть `refresh=true`.
- Файлы до 128 MiB, распакованный Office до 256 MiB, текст до 2 млн символов. Усечение отмечается явно.
- Сканы PDF требуют просмотра/OCR. Аудио и неподдерживаемые форматы скачиваются без выдуманной расшифровки. Старые `.doc` читаются через `textutil` на macOS, если конвертация доступна.
- Внешние ссылки не получают токены. HTTPS проверяет сертификаты; перенаправления с IT cookies запрещены.
- Markdown не сохраняет внешний вид: изображения, сложные формулы и спорные таблицы проверяй по оригиналу.
- Локальные токены, сессии, оценки, учебные материалы и готовые работы не входят в публичный репозиторий. Не добавляй их в Git.

## Проверки

`tests/` использует синтетические HTTP-ответы, небольшие тестовые PDF/Office-файлы и настоящий MCP-протокол. Учётные данные и доступ к университету для тестов не нужны. CI запускает эти проверки отдельно от live-доступа. `requirements.lock.txt` фиксирует рабочее окружение macOS/Python 3.13; для другой платформы устанавливай зависимости из `pyproject.toml`.

Основа интеграции: [Moodle External Services](https://moodledev.io/docs/4.5/apis/subsystems/external), [mobile launch Moodle 3.9](https://github.com/moodle/moodle/blob/MOODLE_39_STABLE/admin/tool/mobile/launch.php), [Microsoft MarkItDown](https://github.com/microsoft/markitdown).
